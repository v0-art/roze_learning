# Развёртывание на VPS

Этот комплект запускает сайт, PostgreSQL и Caddy. Он находится в `compose.vps.yaml`, отдельно от локального `compose.yaml`; текущую локальную базу команда запуска VPS не изменяет. База на VPS хранится в отдельном Docker volume, порт PostgreSQL наружу не открыт. HTTPS настраивает Caddy, если домен указывает на сервер и доступны порты 80 и 443.

## Первый запуск

1. Установите на VPS Docker Engine и Compose. Скопируйте проект на сервер или клонируйте репозиторий. Перед публикацией репозитория проверьте историю Git: исключение файла через `.gitignore` не удаляет его из старых коммитов.
2. Направьте DNS-запись домена на IP сервера и откройте порты 80 и 443. Выполните в каталоге проекта:

   ```sh
   cp .env.vps.example .env.vps
   chmod 600 .env.vps
   openssl rand -hex 32
   openssl rand -hex 32
   openssl rand -hex 32
   ```

   Откройте `.env.vps`, замените `SITE_ADDRESS` своим доменом, а каждый из трёх паролей — отдельным полученным случайным значением. Пароли должны различаться и содержать 32–100 символов латиницы, цифр, `_` или `-`. Для HTTPS оставьте `COOKIE_SECURE=true`. Не публикуйте этот файл и не отправляйте его в чат.

3. Запустите контейнеры:

   ```sh
   docker compose --env-file .env.vps -f compose.vps.yaml up -d --build
   docker compose --env-file .env.vps -f compose.vps.yaml ps
   ```

   При первом старте `migrate` создаёт таблицы, администратора `admin` и ограниченную роль приложения. После этого он завершается; это ожидаемо. Сайт будет доступен по `https://ваш-домен`, вход администратора — по `/platform`. Используйте начальный пароль из `.env.vps` и измените его в кабинете. `INITIAL_ADMIN_PASSWORD` применяется только при создании первого администратора: его последующее изменение в файле не меняет пароль существующей учётной записи.

4. Настройте резервное копирование и проверьте восстановление. Для публичного использования требуется отдельная проверка безопасности и конфигурации сервера.

## Обновление через GitHub Actions

После отправки изменений в `main` workflow `.github/workflows/deploy.yml` запускает проверки и сборку. Только при успехе он передаёт архив того же коммита на VPS по SSH с проверкой ключа сервера. Закрытый ключ подключения и проверенный ключ сервера хранятся в секретах GitHub `VPS_DEPLOY_KEY` и `VPS_KNOWN_HOSTS`; пароли базы и `.env.vps` остаются на VPS. Развёртывания выполняются последовательно.

На VPS ограниченный SSH-ключ запускает `/opt/rozephyr/ops/deploy-receive.sh`. Перед обновлением он требует свободные 2 ГиБ, создаёт проверенную резервную копию и запускает Compose с существующим именем проекта `rozephyr` и файлом `/opt/rozephyr/app/.env.vps`. Копии релизов хранятся в `/opt/rozephyr/releases`, а ссылка `/opt/rozephyr/current` указывает на последний успешно проверенный релиз. Скрипт при установке следует отдельно обновлять из `ops/deploy/receive.sh`: входящий архив не может сам изменить этот обработчик.

Ошибки сборки, миграции, контейнеров или проверки сайта останавливают workflow. Автоматического отката миграций нет; перед повтором неудачного коммита нужно изучить журналы и состояние базы. Каталог неудачного релиза сохраняется, поэтому повтор того же коммита требует ручной проверки и удаления именно этого каталога. Старые релизы автоматически не удаляются — следите за свободным местом. Копии базы на этом же VPS не защищают от потери сервера.

## Данные при первом запуске

Новая база на VPS создаётся **пустой**: существующие курсы и пользователи с вашего компьютера автоматически не копируются. Чтобы перенести их, заранее создайте и сохраните резервную копию действующей реляционной базы по `NEXUS_RUNBOOK.md`, перенесите её на сервер защищённым способом и восстановите в пустую базу до запуска сервиса `migrate`.

Для новой установки, где в базе ещё нет таблиц:

```sh
docker compose --env-file .env.vps -f compose.vps.yaml up -d postgres
docker compose --env-file .env.vps -f compose.vps.yaml exec -T postgres psql -U roze_admin -d rozephyr -c "SELECT count(*) FROM pg_tables WHERE schemaname = 'public';"
# Продолжайте только если результат равен 0 и контейнер postgres healthy.
docker compose --env-file .env.vps -f compose.vps.yaml exec -T postgres pg_restore -U roze_admin -d rozephyr --no-owner --no-acl --single-transaction < /защищённый/путь/backup.dump
docker compose --env-file .env.vps -f compose.vps.yaml up -d --build
```

Не запускайте восстановление поверх действующей базы. Если в восстановленной базе уже есть администратор, используются его существующие учётные данные; новый пароль из `.env.vps` его не заменит. Сверьте курс, учеников и файлы после переноса, затем храните копию отдельно от VPS.

## Резервная копия VPS

В `ops/backup` находятся скрипт и systemd-таймер для ежедневной копии базы в 03:30 по Москве. Скрипт создаёт дамп с правами только для root, восстанавливает его во временную отдельную базу, проверяет доступность таблиц и удаляет временную базу. Удаление старых файлов ограничено собственными файлами `daily-*.dump` старше 13 дней; исходные резервные копии не затрагиваются. При менее чем 1 ГиБ свободного места или недоступной базе создание завершается ошибкой.

Установка на VPS от root после проверки скрипта и путей:

```sh
install -d -m 700 /opt/rozephyr/ops /root/rozephyr-backups/daily
install -m 700 ops/backup/rozephyr-backup.sh /opt/rozephyr/ops/rozephyr-backup.sh
install -m 644 ops/backup/rozephyr-backup.service /etc/systemd/system/rozephyr-backup.service
install -m 644 ops/backup/rozephyr-backup.timer /etc/systemd/system/rozephyr-backup.timer
systemctl daemon-reload
systemctl start rozephyr-backup.service
systemctl enable --now rozephyr-backup.timer
systemctl status rozephyr-backup.timer
journalctl -u rozephyr-backup.service -n 30 --no-pager
```

Эти файлы остаются на том же VPS и не защищают от потери сервера. Требуется отдельное защищённое хранилище и оповещение об ошибке; автоматическая отправка вне VPS и уведомления этим комплектом не настроены. Восстановление приложения и пользовательских сценариев также требует отдельной периодической проверки.

При прямом подключении пользователей к Caddy приложение доверяет только одному прокси, а Caddy заменяет входящий `X-Forwarded-For` адресом подключившегося клиента. Если перед Caddy включён CDN, это будет адрес CDN: для корректных персональных лимитов необходимо отдельно настроить доверенные адреса CDN и проверить защиту от подмены. Не включайте доверие заголовкам при прямой публикации порта приложения.

Команда ниже создаёт дамп текущей базы в файл на хосте. Он содержит персональные данные и хеши паролей.

```sh
umask 077
docker compose --env-file .env.vps -f compose.vps.yaml exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > rozephyr-backup.dump
```

Регулярно переносите зашищённые копии за пределы VPS и проверяйте их восстановление в отдельную пустую базу. `docker compose down -v` удаляет тома с базой и сертификатами: для обычной остановки используйте `docker compose --env-file .env.vps -f compose.vps.yaml down` без `-v`.
