# ГЛАВНОЕ ЗАДАНИЕ ДЛЯ CODEX 6.1
# Внедрение утверждённой архитектуры Rozephyr Learning 3.0

## 0. Источник истины

Ты работаешь с **действующим репозиторием** Rozephyr Learning, в котором владелец уже самостоятельно изменял UI, API и данные. Не создавай новый проект и не применяй старую документацию вместо фактических файлов репозитория. Сперва прочти все документы этого комплекта:

- `docs/00_DECISIONS_AND_TRACEABILITY.md` (R01–R30/C01–C07/UI-EXCEPTION-001);
- `docs/01_REGULATION_V3.md`;
- `docs/02_TECHNICAL_SPEC_V3.md`;
- `docs/03_CONTENT_CONTRACT_V1.md`;
- `docs/04_SESSION_AND_REPORT_CONTRACT_V1.md`;
- JSON Schema из `schemas/`;
- примеры из `examples/`;
- пакетные проверки `qa/`.

Проверь соответствие этим документам реального PostgreSQL-режима, а не только устаревшего JSON backend. Не предполагай, что прежний аудит описывает все поздние изменения владельца.

## 1. Жёсткое требование: интерфейс не менять

**UI-FREEZE-001** запрещает редизайн, новые разделы, смену брендинга, маршрутов, сетки, карточек, кнопок, текста, цветов, типографики, классов CSS, теней, расстояний, иконок, hover/focus, анимаций и responsive-поведения. Сохраняй нынешнюю реализацию. Не выполняй незапрошенный cleanup интерфейса.

**ЕДИНСТВЕННОЕ ИСКЛЮЧЕНИЕ UI-EXCEPTION-001:** заменить **действие копирования JSON учебного занятия** на скачивание персонального архива. Существующая кнопка получает текст **«Скачать архив»** и скачивает `session-package.zip`, не копируя JSON. Положение, размер, стиль, анимации, поведение hover/focus, layout и остальные визуальные характеристики остаются теми же. Если в актуальном UI несколько кнопок «Копировать JSON» (например, экспорт отчёта и выдача учебных данных), меняй только **выдачу пакета занятия**, а не другие кнопки; покажи в отчёте точный компонент. Не добавляй другие кнопки. На вводе отчёта сохраняй существующую форму/обработчик, добавив допустимый ZIP/JSON транспорт без визуального редизайна.

До начала правок сделай baseline-скриншоты текущего UI; после — Playwright visual regression для разных ролей и mobile/desktop. Единственное допустимое отличие по интерфейсу — надпись и функция конкретной кнопки.

## 2. Целевая образовательная модель

Уроки, промежуточные КР и экзамены занимают **общие позиции в одном последовательном плане**, но имеют разные правила проведения. КР может быть блокирующей или неблокирующей; это выбирает ментор для данной КР. Исчерпание пересдач запрещает новые попытки данной аттестации до решения ментора, но не добавляет глобальную блокировку курса. Экзаменационные условия завершения модуля заданы регламентом и опубликованной конфигурацией.

Урок завершён после принятия корректного отчёта, ошибки остаются в истории. ДЗ оценивает внешний ChatGPT, а не ментор. Перед КР отдельная фаза ДЗ, её баллы не участвуют в баллах КР. Экзамен получает билет автоматически от платформы, он фиксируется до выдачи ZIP. Ментор получает сведения о каждой попытке КР/экзамена/пересдачи, включая неуспешную.

## 3. Контракты и внедрение материалов без кода

Используй единый `Rozephyr Content Contract 1.0`: ZIP+manifest+JSON+Markdown. Все документы и примеры — целевой проект, не доказательство наличия реализации. Доработай импортёр до универсального импорта содержимого любого объёма в **существующий курс**.

Импорт: одинаковые ID и неизменённый материал — no-op; изменение — revision N+1 без переписывания прошлых редакций; новая запись — revision 1. Новые редакции — draft, публикует ментор. Ничего не удалять из-за отсутствия в частичном ZIP. Импорт — атомарный (rollback на ошибке). До применения проверить JSON Schema и техническую читаемость архива; **НЕ** анализировать педагогику, науку, содержательные межпредметные связи. Никаких магических исправлений неполных данных. Экспорт должен дать сопоставимый пакет для повторного импорта.

## 4. Входное/выходное взаимодействие с ChatGPT

По действию кнопки «Скачать архив» платформа выдаёт только `session-package.zip` с `START_HERE.md`, полным `regulation.md`, `activity.md`, `context.json`, материалами занятия и, если нужно, билетами/рубриками. Снимок и версия регламента сохраняются в PostgreSQL, точно привязаны к ученику, мероприятию и попытке. Для первого урока не выдумывать прежнюю историю. Для любого следующего — полные незакрытые ДЗ и обязательные проверки, приоритеты знаний и компактное резюме остального. Больше не полагаться на спецхардкод M01-T01-U01→U02.

По итогам принимать `session-result.zip` с `report.json`; если внешний ChatGPT не умеет архивировать — принимать отдельный `report.json` той же схемы. Платформа **доверяет принятому отчёту** и не ведёт независимый антифрод. Сохранение истории, статусы ДЗ/пробелов и уведомления выполняются детерминированно. Пробел закрывается после успешной перепроверки, указанной в принятом отчёте.

Важно: работа ChatGPT с ZIP в выбранной модели не гарантирована. Реально испытать распаковку/чтение архивов и генерацию результата; не заявлять об успехе при отсутствии такого теста. Не изменять пользовательский сценарий самостоятельно, если ZIP не поддержан.

## 5. Миграция

По утверждённому решению владельца на текущем этапе **реальных учеников нет**. Создай резервный архив доступного содержимого; один раз преобразуй старые NEXUS-пакеты, уроки, банки, билеты и граф знаний в новый формат. Не считай демо-отчёты реальными результатами. Удалять старую рабочую поддержку импорта можно **только после проверенного преобразования и отдельной возможности восстановления**. Исходные материалы не терять.

## 6. Порядок работ

1. Изучи repo, git status, рабочий реляционный режим, базовые сценарии и визуальный baseline. Не уничтожай незакоммиченные правки владельца.
2. Сопоставь актуальную реализацию с требованиями R01–R30 и спецификациями; кратко сохрани AS-IS/TO-BE матрицу.
3. Утверди внутри репозитория машинные типы схем и примеры; реализация должна читать именно единый контракт, не дублировать неявные правила.
4. Реализуй единый механизм допуска по последовательности уроков/КР/экзаменов, сохранив существующие компоненты UI.
5. Реализуй регламент в ZIP сессии и постоянное версионирование, универсальный перенос ошибок/ДЗ.
6. Реализуй типизированные отчёты, попытки КР/экзамена, билеты, локальные блокировки и уведомления.
7. Реализуй повторный импорт с no-op/version, атомарный rollback, Export→Import→Export.
8. Мигрируй существующее содержимое с резервной копией; проверь точные ID/тексты/количества.
9. Прогони 3 последовательных урока, затем КР и экзамен на **изолированном тестовом ученике**, PostgreSQL, браузер; сравни визуал до/после.
10. Передай отчёт по критериям приёмки AT-01–AT-24, укажи что проверено, что ограничено внешней поддержкой ZIP и какие исходники изменены.

## 7. Абсолютные запреты

- Не менять дизайн, тексты лендинга и остальные кнопки.
- Не подменять ZIP текстовым промптом или JSON после явного решения владельца.
- Не подключать LLM API в сайт.
- Не оценивать педагогический смысл JSON учебного пакета на сервере.
- Не перезаписывать старые опубликованные версии.
- Не автоматически публиковать новую редакцию.
- Не сбрасывать учебную историю без отдельной доказанной миграции.
- Не создавать некорректные фиктивные отчёты ради зелёного теста.
- Не заявлять об окончании без проверки реляционного режима и E2E.
