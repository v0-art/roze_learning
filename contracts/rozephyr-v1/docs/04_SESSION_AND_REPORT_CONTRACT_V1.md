# ROZEPHYR SESSION & REPORT CONTRACT 1.0
# Пакеты персональных занятий и возвращаемых результатов

**Редакция:** 1.0 · **Дата:** 10.11.2026 · **Статус:** целевой проект контракта, требующий испытания реального внешнего ChatGPT.

## 1. Разделение данных

Сессия (`session-package.zip`) — **вход** конкретного ученика во внешний ИИ. Результат (`session-result.zip`) — **выход** внешнего ИИ в платформу. Они не содержат весь контентный курс. У них разные манифесты и разные схемы. Результат может быть представлен одиночным `report.json` как резервный способ, без замены единой схемы данных.

## 2. Состав входного ZIP

```text
session-package.zip
├── manifest.json          # Rozephyr Session Package 1.0
├── START_HERE.md          # точка входа; как читать и начать занятие
├── regulation.md          # полный текст действующей версии регламента
├── activity.md            # педагогические инструкции конкретного мероприятия
├── context.json           # только необходимые предыдущие знания, ДЗ и пробелы
├── content/               # фактический учебный материал данного мероприятия
│   └── blocks.md
└── assessment/            # присутствует только у КР/экзамена
    └── assignment.md
```

`manifest.json` закрепляет `sessionId`, `studentRef`, `courseId`, `itemId`, `itemType`, `itemRevision`, `regulationRevision`, `createdAt`, `files[]`. `studentRef` непрозрачен и не содержит ненужных персональных данных. Каждый выданный ZIP сохраняется как неизменяемый снимок в БД. Полный текст регламента — в ZIP, не ссылка на живой документ.

**UI-EXCEPTION-001:** существующая кнопка выдачи учебного материала «Копировать JSON» получает надпись **«Скачать архив»** и скачивает `session-package.zip`. Никакие другие элементы интерфейса не меняются. На сервере при клике создаётся или повторно выдаётся ZIP той же сессии с корректным `Content-Type: application/zip` и безопасным именем файла. Кнопка не должна копировать JSON в clipboard.

## 3. Единственный вход для внешнего ChatGPT

Ученик скачивает **только ZIP**, загружает его в ChatGPT и просит: «Открой START_HERE.md и следуй приложенному регламенту». `START_HERE.md` содержит явные инструкции: прочесть `manifest.json`, `regulation.md`, `activity.md`, `context.json`, содержимое `content/`, не менять формат отчёта, по окончании вернуть `session-result.zip` либо `report.json`. Внешняя модель должна следовать регламенту именно этого снимка сессии.

**Эксплуатационная неопределённость:** не всякий режим ChatGPT способен просмотреть ZIP либо создать скачиваемый ZIP. До запуска в продуктивном сценарии требуется реальная проверка. Не заявлять о совместимости без испытания. При невозможности прочитать ZIP сценарий R21 остаётся невыполненным — не менять самовольно требование на простой текст.

## 4. Контекст непрерывного обучения

`context.json` содержит: `openHomework[]` с полным текстом каждого неуспешно закрытого ДЗ; `mandatoryRechecks[]` с конкретными идентификаторами ошибок из любых прошлых уроков; `relevantSkills[]`, `priorSummary`, `closedGapIds[]` при необходимости информационно. Хранилище сохраняет полную историю; ZIP — актуальное обязательное + краткое резюме. После принятой успешной перепроверки пробел закрывается окончательно в учётной модели и исчезает из обязательного списка. Исходная оценка урока остаётся неизменной.

Пропуск «входного контроля» для М01-Т01-У01, переходы между темами/модулями и прохождение КР не могут обнулять ДЗ и нерешённые ошибки. Для обычного урока порядок: все ДЗ → все ошибочные/частичные вопросы → другие важные знания → новая проблемная задача → теория → «Дальше» → «я не умру чмом» → диагностика → ДЗ → отчёт. Для КР перед самостоятельной работой допускается отдельная фаза проверки ожидающего ДЗ, не входящая в баллы контрольной. Экзамен не является лекцией.

## 5. Выходной ZIP / JSON

```text
session-result.zip
├── report.json             # обязательный структурированный результат
└── attachments/            # необязательные файлы, не меняющие обязательные поля
```

В `report.json` обязательны: `format`, `formatVersion`, `sessionId`, `itemId`, `itemType`, `status`, `submittedAt`, `result`, `entryControl`, `knowledgeGaps`, `strongSkills`, `nextContext`. Типизированный `result` зависит от `itemType`: диагностический итог урока; проценты/официальный результат КР; ticketId/версия банка/критерии/результаты экзамена. `entryControl.homeworkResults` фиксирует результаты проверки прежних ДЗ, а `entryControl.recheckResults` — действия по прежним ошибкам. Весь результат принадлежит конкретному sessionId.

**Одиночный JSON** допустим как резервный вариант, если внешняя модель не способна сформировать ZIP. Он должен проходить **ту же** схему `report.schema.json` и давать тот же результат сохранения.

## 6. История и статус

Платформа доверяет формально корректному отчёту пользователя, не выполняет независимой антифрод-проверки. `source = external_ai_user_submitted` фиксируется как происхождение. Для закрытия пробела достаточно статуса успешной перепроверки в принятом отчёте. Ментор не обязан подтверждать обычные ДЗ. Отчёт КР/экзамена/пересдачи создаёт обязательную запись для ментора при любом результате.

Структурно некорректный ZIP/JSON отклоняется без частичных записей. Повторный импорт того же `sessionId` и того же результата не создаёт вторую попытку. Подмена существующего отчёта другими значениями по тому же sessionId не должна незаметно переписывать историю — нужна явная ошибка конфликта.

## 7. Валидация

Валидация JSON Schema обязательна. Платформа дополнительно выполняет техническую проверку ZIP, размеров, путей, принадлежности сессии пользователю и невозможности переписать чужой результат. Не проверяет предметную истинность ответов или добросовестность ученика. Не угадывает отсутствующее поле `ticketId`, баллы или ID ошибки.

## 8. Фазовые проверки и единая последовательность

**lesson:** следующая диагностика после предыдущей попытки обязательна по регламенту. Входная проверка включает ДЗ/ошибки/другие ключевые знания; ошибки сохраняются до подтверждённого в принятом отчёте успешного повторного результата. Урок завершается при принятии корректного отчёта.

**control_work:** начало содержит изолированную проверку ожидающих ДЗ, затем контрольную. КР входит в общий учебный план, её `blocksNext` задаёт ментор. Не включать баллы ДЗ в оценку КР.

**exam:** билет определяется платформой до генерации ZIP и не изменяется в данной попытке. Ограничение повторов 1+3; уведомление ментора до третьей пересдачи и после каждой попытки. Исчерпание попыток само по себе не блокирует весь курс.

## 9. Проверочные сценарии

- Технически корректный входной ZIP открывает точный регламент 3.0 и предметное содержимое урока.
- Скачиваемый ZIP формируется именно кнопкой «Скачать архив», прежний HTML/CSS кнопки сохраняется.
- После первого отчёта следующий ZIP содержит полные официальные ДЗ и все обязательные ошибки.
- После успешной повторной проверки пробел исключается из обязательного реестра, но история остаётся.
- Контрольная проверяет ДЗ до старта оцениваемой части, не повышая/понижая её баллы.
- Тот же report.json импортируется как ZIP и отдельно с одинаковым результатом; повторный импорт идемпотентен.
- Неизвестная версия/чужой sessionId/опасный ZIP отклоняются по техническим причинам.
