# Rozephyr Learning: локальный запуск

Для отдельного размещения на VPS см. [инструкцию Docker](docs/VPS_DOCKER.md). VPS-конфигурация не переносит локальные данные автоматически.

1. Запустите Docker Desktop и дождитесь запуска контейнера PostgreSQL. Если контейнер остановлен, в терминале проекта выполните `docker compose up -d`.
2. Установите зависимости командой `npm ci`, если они ещё не установлены. Для разработки нужен Node.js 24.
3. Выполните `npm run dev` и откройте адрес, указанный в терминале. Приложение использует реляционную базу PostgreSQL, адрес которой хранится в локальном файле `.env.relational`.
4. Обычные кабинеты открываются через кнопку «Войти» на главной странице. Существующие учётные записи — `mentor` и `student`, их прежние пароли не изменены. Кабинет администратора платформы расположен по адресу `/platform`. Начальные учётные данные администратора находятся в `.env.initial-admin`; после входа измените пароль в его кабинете и удалите этот файл.

Администратор создаёт менторов и управляет их доступом к платформе; курсы и ученики принадлежат менторам. Ментор создаёт курсы, приглашает других менторов, закрепляет учеников, публикует материалы и проверяет результаты. Настройки и данные не следует публиковать в Git.

## Резервные копии

`npm run db:backup` создаёт дамп **текущей реляционной базы** в `data/backups/`. Архив содержит личные данные и хеши паролей; храните копию отдельно и ограничьте к ней доступ. Команда ожидает работающий Docker Compose и доступную команду `docker`. В WSL без интеграции Docker можно указать путь к Docker Desktop через переменную `NEXUS_DOCKER`.

Восстановление проверялось на отдельной временной базе через `pg_restore --no-owner --single-transaction`: данные всех таблиц совпали с оригиналом. Для восстановления в рабочую базу сначала остановите приложение, сохраните свежую копию, восстановите дамп в новую пустую базу PostgreSQL, настройте для неё отдельную роль приложения командой `npm run db:relational:permissions` и измените адрес в `.env.relational`. Не восстанавливайте старый дамп поверх работающей базы.

Дамп до переноса и исходная база сохранены отдельно. В перенос не вошли четыре старых задания без указанного ученика по принятому решению; они остались в исходной базе и её резервной копии. При переносе четырёх файлов библиотеки сохранены сами файлы, исходные и вычисленные контрольные суммы; прежние суммы не совпадали с содержимым и требуют отдельной проверки.

## Проверки

`npm test`, `npm run lint`, `npm run build` и `npm run test:postgres` проверяют приложение и сервер. `npm run test:e2e:relational` запускает браузерный сценарий на отдельной временной базе; для него нужен установленный Chromium Playwright. Тесты PostgreSQL создают и удаляют только собственные временные базы.

Старые команды `dev:postgres`, `dev:json`, `db:legacy:backup` и `db:legacy:restore` оставлены для обслуживания старой версии и её базы; они не работают с текущими данными приложения. После начала работы в новой базе эти данные расходятся с архивной версией.

Локальные секреты, рабочие данные и дампы исключены `.gitignore`. Старые коммиты Git могут содержать ранее отслеживавшийся файл данных; перед публикацией репозитория следует отдельно проверить историю. Для публичного размещения необходимы HTTPS, защита сервера и отдельная проверка безопасности и резервирования.
